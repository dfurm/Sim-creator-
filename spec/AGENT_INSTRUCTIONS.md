# Implementing a block from this baseline

1. Read PROJECT_SCOPE, the controlled simulation record and matching brief. Pin the version. Choose the labelled starter formulation; bring deferred variants through their own gates.
2. Identify a reusable model or solver, units, parameter owners, boundary conditions and semantic anchors before adding a view. The model must run in isolation without React, WordPress, Recipe Lab or Master.
3. Convert the independent fixtures, invalid cases, limits, conservation and round-trip conditions into tests. A test generated by the same production formula is insufficient as the only verification.
4. Implement explicit input modes, reasoned validity, suppression and provenance. Supply keyboard/numeric alternatives, a table, log handling and stable IDs. Simulated output must be distinguishable from measured output.
5. Verify in standalone and embedded hosts using the same state. On change, update status, decisions, references, affected snapshots and tests. Submit the scientific, educational and licence evidence to the named release owner before a published version.
6. Treat published model content, reference data and lesson pins as immutable. Derived briefs are regenerated from approved records. Do not develop physical actuator control in a simulation adapter.
