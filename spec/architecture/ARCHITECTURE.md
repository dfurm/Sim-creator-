# Web-native architecture and technology selection

Use a static TypeScript application compiled to JavaScript, with a small React view shell, SVG for annotated equipment and modest plots, native HTML inputs/tables, and locally bundled KaTeX with accessible mathematical text. Use Vite to build immutable versioned assets. Never run executable equations from a scenario. Model packages expose pure functions and an optional state integrator. All renderers consume the same calculated values the learner can export. An academic can publish a scenario by configuration; adding a novel physical model still requires reviewed code.

| Technology | Trade-off across maintenance, speed, numerical accuracy, deployment and access | Decision |
|---|---|---|
| TypeScript / JavaScript | Types catch contract drift, TS compiles away; both use JS binary64 numbers. Types alone cannot check dimensions or physical validity. Small static bundle works on mobile/offline. TS Apache-2.0 [TS]. | TS for public interfaces, pure kernels and tests; no heavy runtime required. |
| React / native custom elements | React MIT, maintainable state and accessible DOM; rendering on every simulation tick wastes CPU. Native elements have a host-independent lifecycle but still need accessible controls and styles [REACT, CUSTOM]. | React for first shell; expose a thin custom element when a host needs same-page integration. Vue/Svelte viable alternatives; changing view must not change kernels. |
| SVG / Canvas / WebGL | SVG exposes semantic nodes and handles hundreds of elements. Canvas trades DOM semantics for dense raster speed; WebGL has GPU/context variability, no inherent text/keyboard alternative. No scientific accuracy comes from a renderer. | SVG first. Use Canvas for dense images/large traces with table equivalents. Use WebGL only after measuring a genuine large-field need; keep CPU reference scene. |
| Small SVG plots / D3 / Plotly.js | D3 scales/shapes modular, ISC [D3]; Plotly.js MIT [PLOT], many trace types/export, larger bundle. Neither guarantees a readable scientific graph on a phone. | Use labelled lightweight SVG paths and tables first. Lazy load plotting library only for dense scientific interactions. |
| KaTeX / MathJax | KaTeX MIT [KATEX], fast local typesetting; MathJax Apache-2.0 [MATHJAX], richer features. Both need assistive-technology testing. | KaTeX HTML+MathML, plain-text fallback. Assess MathJax if required notation or speech support fails local tests. |
| Numerical libraries, units, math.js | General engines simplify units/matrices but parsing arbitrary expressions complicates reproducibility. Binary64 needs conditioning, residual checks and known benchmarks. | Implement small reviewed analytic kernels and dimension maps; use a vetted QR/statistical special-function dependency when necessary. Lock versions and notices. |
| Web Workers / WASM | Workers avoid blocking interaction; structured cloning costs memory. WASM enables compiled solvers; numerical parity, initial payload and mobile memory matter [WASM, WORKER]. | Add cancellable worker after profiling. WASM only for a qualified solver/property package. Never make the DOM or a remote service part of the model. |
| Python / server services | SciPy useful for independent reference runs; scientific Python in a browser adds runtime size. Servers add network, availability, privacy and ongoing support costs. CoolProp core and optional backends have different terms [SCIPY, COOL]. | Python offline QA/authoring. Precompute versioned specialist fields where interpolation is defensible. Optional queued, cancellable service only for justified F5 jobs with retained reproducible inputs. |
| Static hosting / iframe / web component | Static URLs are easy to version and cache; iframe isolates host CSS/JS, requires a message trust boundary. Web components allow direct DOM integration in trusted hosts [CUSTOM, MSG, OFFLINE]. | Static HTTPS, iframe-first for WordPress and LMS, new-tab fallback. Bundle for local web serving or explicit standalone-file export. |

## Repository contract

Proposed source folders: packages/model-core (registry, parameter graph, SI units), packages/science (properties, correlations, geometry-specific scale definitions), packages/solvers (root, RK, tridiagonal, regression), packages/runtime (clock, events, scenarios, state), packages/views (SVG primitives, charting, math, accessible tables), packages/learning (activities and assessment predicates), packages/adapters (embed, CSV, local host, later LMS), apps/web, simulations/<id>/<version> and tests/golden. This delivered tree is its documentation baseline. IDs persist through title and layout changes.

A declaration supplies modes, typed controls, SI bounds, steps, defaults, linked outputs, semantic anchors, fixed inputs, learning scenarios and sources. Use a dependency DAG for derived variables. For inverse problems change the independent-variable set explicitly; never leave a target and a calculated outcome editable together. Apply atomic input batches and reject invalid combinations without partially updating the state. Compute outputs, rule results, plot data and a data summary from one revision. Ignore stale worker results using instanceId + revision. Separate physics clock from requestAnimationFrame; run a bounded number of steps, report backlog/drop render frames without skipping physical integration.

**Reuse boundaries.** Geometry + unit conversions + Reynolds scales + friction kernel → pipe, network, pump duty and sizing. Slab resistance and terminal temperature helpers → wall, insulation, exchanger and utilities. FOPDT/sampler + optional controller → control tutorials and simulation-only Master playback. Binary equilibrium methods → flash and distillation, with a variant for fixed-T pressure and a separately declared constant-α design surrogate. Same inputs and names are not enough to reuse a model across boundary conditions.

**Renderer catalogue.** Pipe segment, reducer, elevation marker, tap and vector rake; vessel inventory/ports; radial or planar layer; reactor concentration region; two-stream exchanger with reversible orientation; valve travel and pump icon; dimension line, reference datum and clipped contour fill; arrows with scale; labelled axes, annotated point, interval band and calibration marker. Composite wall and tank are configurable compositions. Blasius profiles, McCabe–Thiele stepping, covariance plots and Levenspiel areas require custom scientific drawings. Specify whether each primitive represents geometry, a measured field, a derived field or a qualitative illustration.

**Performance budgets (provisional engineering targets).** Cold shell plus one analytic block ≤350 kB compressed JS excluding optional bundled fonts; median input-to-stable-output <50 ms, p95 <100 ms on a documented midrange Android test device. Use 10–20 Hz text/plot updates during motion, ≤30 fps for scene; settle synchronously on keyboard commit. Bound imported CSV to 5 MB/100k rows for first release, downsample only the view, preserve raw data. Worker decision if repeated model work exceeds 16 ms on reference device. Test last two supported releases of Chrome, Edge, Firefox, Safari plus iOS Safari and Android Chrome; print exact tested versions at release.
