# WordPress and standalone delivery

Publish a static catalogue at a first-party HTTPS path or a dedicated subdomain such as sims.furmtech.com.au. Choose the separate origin if DNS and hosting permit; this is a proposed address. WP page holds introduction, objectives, versioned iframe, title and fallback link. The model, solver, fonts and datasets are self-hosted static assets with immutable content hashes. No WP rewrite, PHP numerical computation, user account or analytics service is required. Verify editor permissions and sanitisation because WordPress can strip disallowed iframe markup [WP]. If necessary, provide an administrator-managed shortcode restricted to the Furmtech origin and simulation IDs. Confirm staging behaviour with actual theme, caching plugin and a logged-out mobile visit.

Use versioned paths /sim/S11/1.0.0/ and /scenario/<id>/<version>; a catalogue “latest” link may move but academic links never do. A blocked iframe shows a visible open-in-new-tab link. Configure frame-ancestors for approved hosts including the institution's entire embedding chain. Grant only required frame permissions. Do not combine arbitrary untrusted same-origin content with a permissive sandbox. Keep local files/data in the user's browser. Check origin and source window and validate every message against the protocol, restrict payload size, match nonce and requestId, and reject commands before handshake. Set explicit targetOrigin [MSG]. A null/file origin uses an in-process offline host, not wildcard trust. No executable content in imported configuration; parse CSV as data, neutralise spreadsheet formula injection on export of text fields.

Start staging with only the declared origin, anonymous sessions and local export. Test failure cases: no network after offline download, blocked storage, missing version, malformed input, old recipe state, message from wrong origin and iframe unable to embed. If release changes results, publish a new immutable version and preserve old assets. Roll back catalogue pointers only. Re-run paired tests before class use.
